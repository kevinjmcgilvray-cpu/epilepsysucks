For the engineers

Behind the code

Janitor in the daytime, junior software engineer by nighttime. I built and still run this entire site myself — no agency, no template. It's a plain static page (no framework) backed by a handful of serverless functions and a Postgres database, and the source is public if you want to poke around.

The frontend is deliberately boring: hand-written HTML/CSS/JS, no build step, no bundler. Every chart on this page — the weigh-ins, the seizure-frequency bars — is plain SVG built and animated by app.js, with no charting library. The backend is a set of small Vercel serverless functions in api/, each one reading or writing a Neon Postgres database (training runs, weigh-ins, milestones, fundraising totals, comments, race-day GPS).

Every change ships the same way: a feature branch, a pull request with its own live Vercel preview URL, then a squash merge to main that Vercel auto-deploys straight to this domain — usually within a minute or two of merging.

This site used to be one really long index.html — hero, story, recovery, marathon, and community all on a single scroll, stitched together with #anchor links. It worked, but every new section made that one file (and one page load) heavier, and the nav's dropdown links were really just scrolling the same page rather than going anywhere.

So I split it into 5 real pages — /, /journey, /recovery, /marathon, /community — each its own static HTML file. The nav, footer, race-clock countdown, and entry warning still live in exactly one place each, in partials/*.html; a small build script (scripts/build.js) splices them into every page via <!-- INCLUDE:partials/xxx.html --> markers before anything deploys, so there's still only one copy of the header to update, not five. Every paragraph that moved pages was sliced out of the old file by its exact line range rather than retyped, so nothing changed by accident along the way.

Old bare #anchor links still work — hash fragments never reach the server, so that redirect runs client-side off the homepage instead, matching each old anchor to its new page.

Nothing above happened as one big rewrite — it’s been 50-plus small, reviewed pull requests, each one on its own branch with its own live Vercel preview before merging to main (see “The stack” above for exactly how). After an early stretch of fairly organic feature work — the Electric Purple rebrand, live Strava-synced training data, splitting one long page into five — work since has moved through three more deliberate passes: a cleanup pass (clean URLs, accessibility fixes, a new resources page), a structure-and-SEO pass (every section split into its own real sub-page, with breadcrumbs and a full heading-hierarchy audit), and the safety-and-redesign pass that’s in progress now.

As of this writing, Phase 3 is two pull requests in — removing the flashing-lightning effect and adding this very page’s About/Privacy footer links — with a nav rework, a global CSS baseline, and a final consistency pass still queued.
